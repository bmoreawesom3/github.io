The widgets on the display

CPU, GPU, fan/pump, and RAM/storage monitors, each pulling live readings from HWiNFO64.

I built this to get real hardware telemetry onto my Corsair Xeneon Edge display instead of the generic stats iCUE ships with. HWiNFO64 already reads every sensor on the system, so rather than re-implementing that, I wrote a small local service that exposes HWiNFO's shared-memory data as JSON, then built widgets on top of it that poll for live readings and render them on the display.

How it works

  • HWiNFO64 reads hardware sensors via shared memory (Global\HWiNFO_SENS_SM2).
  • A Python bridge service (server.py) exposes that data as JSON over HTTP on localhost:8228.
  • Widget frontends (HTML/JS) poll the bridge and render live readings on the Xeneon Edge display.
  • Drive space monitoring reads directly from Windows system calls, independent of HWiNFO.

Widgets

  • CPU: frequency, core voltage, power draw, and VRM temperature, with two configurable load/temperature gauges.
  • GPU: fan RPM and VRAM usage as gradient bars, plus clock speed — sensor selection favors the discrete GPU to avoid conflicts with integrated graphics.
  • Fans/pumps: four independent RPM bars with freely-editable names, so generic HWiNFO labels can be replaced with real ones.
  • RAM/storage: memory utilization as a gradient bar (percent and GB) plus two selectable drive-space bars.

Every sensor field in every widget is a dropdown populated from the machine's own live hardware, so setup is point-and-select rather than hand-editing config files. Each widget also supports color and background customization and auto-scales its gauges to the sensor's actual range.
